# Bonus Lab — Update Your Interview Strategy Doc

---

## Where This Picks Up

Back in Week 1, before you'd built a single project in this course, you put together an interview strategy doc — your positioning, your talking points, the story you'd tell about yourself in an AI PM interview.

That doc was written from where you stood on day one. Since then you've planned a product, built a full application with Claude Code, added memory to it, secured it, deployed it, built an agent, and worked through red-teaming. You have real stories now — specific decisions you made, problems you ran into, and how you solved them. None of that was in the original doc, because none of it had happened yet.

This lab isn't about writing a new strategy doc from scratch. It's about handing Claude the one you already have, telling it what you've built since, and letting it fold that experience into your interview stories — so the doc reflects the person who finished this course, not just the person who started it.

## Step 2 — Invoke the Skill

Open Claude Code and run:

```
/skill_name <whatever the name of the skill is>
```

Claude will ask you for your **old interview strategy doc** — the one you wrote in Week 1. Have it ready to paste in or point Claude to the file path.

---

## What Happens When You Run It

1. **You provide the old doc.** Claude reads your original positioning and talking points so it knows your starting point.
2. **Claude asks what you've built.** Walk it through the projects and moments from this course that turned into real stories — a tricky bug you tracked down, a design decision you had to defend, a security issue you caught, a feature you shipped end to end.
3. **Claude updates the doc.** It weaves your new stories into the existing structure — sharpening your positioning with concrete, recent proof instead of leaving it generic.

**Output:** an updated version of your interview strategy doc, grounded in what you actually built this cohort.
